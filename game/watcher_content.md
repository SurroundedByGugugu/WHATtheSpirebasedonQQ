# 观者实现与交互说明

## 内容范围

单人主流程新增观者（角色编号 `6`），72 点生命、3c、至纯之水；初始牌组为四张打击、四张防御、暴怒和警惕。

- 75 张紫色牌及其升级：4 张初始、19 张普通、35 张罕见、17 张稀有。
- 8 张衍生牌：奇迹、洞见、惩恶、平安、以暴易暴、贝塔、欧米伽、灭除之刃。
- 3 种专属药水：瓶装奇迹、姿态药水、仙馔密酒。
- 9 件专属遗物：至纯之水、手摇鼓、两仪、泪滴吊坠、斗篷扣、黄金眼、美琅脂、圣水、紫色莲花。

角色、卡牌奖励、药水及遗物池已接入现有注册与归属筛选。圣水替换至纯之水。原有 `card.deva_form` 保持同一 ID，归属改回观者；旧工厂入口兼容调用新定义。天人形态逐回合增加当回合能量，不增加永久能量上限。

联机与 PVP 使用独立战斗引擎，本次未开放这些模式的观者入口。

## 姿态与伤害

`PlayerState.stance` 是唯一姿态字段，取值为 `none/calm/wrath/divinity`。`game/stances.py` 统一切换，重复进入当前姿态不会触发离开或进入奖励。

| 姿态 | 行为 |
| --- | --- |
| 无 | 无额外效果 |
| 平静 | 离开获得 2c，紫色莲花改为 3c |
| 愤怒 | 造成与受到的攻击伤害乘 2 |
| 神格 | 进入获得 3c，造成攻击伤害乘 3，下回合开始退出 |

姿态倍率参与攻击伤害修正与预览，在格挡结算前应用；效果伤害和失去生命不享受倍率。已经修正过的攻击使用 `stance_applied=True` 进入底层伤害函数，避免重复乘算。真言每累计 10 层进入神格，并记录本场累计获得量供光辉使用。

## 预见与选择

抽牌堆继续按既有顺序显示。底层列表末尾是牌堆顶，预见列表的 `[0]` 是下一张抽到的牌。

```text
/card new 6          创建观者单人流程
/card scry 0 2       将预见列表的第 0、2 张牌放入弃牌堆
/card 预见 0 2       同上
/card scry skip      全部保留
/card pick 0         提交观者单项选择
/card pick 0 1       提交升级冥想的两项选择
```

预见允许选择任意数量，未选中的牌保持原顺序。选项按卡牌实例校验，重复或越界编号不会改变牌堆。空抽牌堆不为预见而洗牌；预见弃牌不触发“从手牌弃牌”的效果。预见结束统一触发涅槃、迂回等联动，黄金眼增加检视数量。

`game/resolution.py` 保存尚未执行的战斗步骤。需要选择时暂停当前卡牌、事件、抽牌或敌人行动；提交后先续接内部步骤，再继续外层步骤。例如斩破命运先伤害、等待预见，再抽牌；美琅脂先完成洗牌后的预见，再继续抽牌；通晓万物的两次出牌分别完整结算。

等待选择期间可以查询手牌、抽牌堆和状态，不能另行出牌或结束回合。选择仍通过现有 `PendingChoice` 管理，避免另外建立不一致的交互状态。

续接队列含内存中的生成器和回调，不是可序列化存档。现有读档使用进入节点前的快照；若以后支持保存战斗中任意时刻，需要将续接步骤改为可序列化的数据结构。

## 实现入口与验证

- `data/card/character/watcher_cards.py`：卡牌数据、升级与奖励清单。
- `game/watcher.py`：卡牌效果、保留成长、姿态/预见/回合等事件联动。
- `game/generated_cards.py`：战斗生成卡牌的操控现实升级入口。
- `game/stances.py`、`game/scry.py`、`game/resolution.py`：通用机制。
- `test_py_save/test_watcher.py`：全部基础与升级牌的结算冒烟测试，以及姿态、预见、连续攻击、自动出牌、遗物、药水、保留和跨角色生成卡联动测试。

回归命令：

```text
python -B -m pytest -q -s -p no:cacheprovider test_py_save test_game_service.py
```
